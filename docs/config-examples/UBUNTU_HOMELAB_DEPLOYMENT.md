# Production Deployment Guide: Ubuntu Home Lab

This comprehensive guide details the step-by-step process to deploy the Trading Report Monitor system on a fresh Ubuntu Server (22.04 LTS or 24.04 LTS) in a home lab environment.

## Prerequisites

- **Hardware**:
  - Dedicated machine or VM (Virtual Machine)
  - Minimum: 2 vCPUs, 4GB RAM, 20GB Disk
  - Recommended: 4 vCPUs, 8GB RAM, 50GB SSD
- **OS**: Ubuntu Server 22.04 LTS or 24.04 LTS
- **Network**: Static IP address recommended (e.g., `192.168.1.100`)
- **Domain**: A domain name (optional, but recommended for HTTPS)

---

## Phase 1: Server Preparation

### 1. System Update
Log in to your server and update all packages to ensure security and stability.

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git make unzip apt-transport-https ca-certificates gnupg lsb-release
```

### 2. Install Docker & Docker Compose
We will install the official Docker Engine.

```bash
# Add Docker's official GPG key
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Set up the repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Verify installation
docker --version
docker compose version
```

### 3. Configure User Permissions
Allow your user to run Docker commands without `sudo`.

```bash
sudo usermod -aG docker $USER
# Apply changes immediately
newgrp docker
```

### 4. Configure Firewall (UFW)
Secure your server by allowing only necessary ports.

```bash
# Deny all incoming by default
sudo ufw default deny incoming
# Allow all outgoing
sudo ufw default allow outgoing

# Allow SSH (Change 22 if you use a custom port)
sudo ufw allow 22/tcp

# Allow HTTP/HTTPS (for Nginx/Traefik later)
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Allow N8N Dashboard (Local LAN only - Recommended)
# Replace 192.168.1.0/24 with your home subnet
sudo ufw allow from 192.168.1.0/24 to any port 5678

# Enable Firewall
sudo ufw enable
```

## Phase 2: Project Installation

### 1. Clone Repository
Navigate to your preferred installation directory (e.g., `/opt`).

```bash
# Create directory and change ownership
sudo mkdir -p /opt/trading-report
sudo chown $USER:$USER /opt/trading-report
cd /opt/trading-report

# Clone the repo (replace with your actual repo URL)
git clone https://github.com/yourusername/trading-report.git .
```

### 2. Environment Configuration
Setup the production environment variables.

```bash
# Copy the production template
cp docs/config-examples/.env.production .env

# Secure the file
chmod 600 .env

# Edit the configuration
nano .env
```

**Critical Variables to Set:**
- `POSTGRES_PASSWORD`: Generate a strong password (`openssl rand -base64 24`)
- `WEBHOOK_SECRET_KEY`: Generate a strong key (`openssl rand -hex 32`)
- `ANTHROPIC_API_KEY` or `GROQ_API_KEY`: Your AI provider key
- `TRADING_PORTAL_USERNAME` / `PASSWORD`: Credentials for the target portal
- `SMTP_*`: Email settings for notifications
- `TELEGRAM_*`: Bot token and Chat ID (optional)

### 3. Create Docker Override (Optional but Recommended)
Optimize for a production home lab server.

```bash
cp docs/config-examples/docker-compose.override.example.yml docker-compose.override.yml
nano docker-compose.override.yml
```

*Recommendation: Uncomment the "EXAMPLE 2: Production Environment" or "EXAMPLE 9: With Custom Health Check Intervals" sections.*

### 4. Configure Gmail API Credentials (If using Gmail)
If you are using the Gmail API (instead of standard SMTP), you need to transfer your `credentials.json` and `token.pickle` files. These files contain sensitive authentication data and are **not** included in the git repository.

**Note**: `token.pickle` is generated by running `generate_gmail_token.py` locally, as it requires a web browser for the OAuth consent screen. You cannot generate it on a headless server.

**On your local machine (where you developed the project):**
Use `scp` to securely copy the files to your server.

```bash
# Replace user@192.168.1.100 with your server details
# Replace /opt/trading-report with your server's installation path

scp services/notification-service/credentials.json user@192.168.1.100:/opt/trading-report/services/notification-service/
scp services/notification-service/token.pickle user@192.168.1.100:/opt/trading-report/services/notification-service/
```

**On the server:**
Verify the files are present:
```bash
ls -l services/notification-service/
# You should see credentials.json and token.pickle
```

## Phase 3: Deployment

### 1. Build and Start
Use the `make` command for a clean production start.

```bash
# Build images
make build

# Start in production mode (detached)
make prod
```

### 2. Verify Services
Ensure all containers are up and healthy.

```bash
# Check container status
docker compose ps

# Check logs for any immediate errors
docker compose logs -f --tail=50
```

### 3. Initialize Database
The database should initialize automatically, but you can verify it.

```bash
# Check database logs
docker compose logs postgres | grep "database system is ready to accept connections"
```

### 4. Verify Health
Run the health check against the monitoring service.

```bash
curl http://localhost:8003/api/v1/health/status
```
*Expected output: JSON response with `overall_status: "healthy"`.*

## Phase 4: N8N Workflow Setup

### 1. Access N8N
Open your browser and navigate to: `http://<SERVER_IP>:5678`

1. Create your admin account.
2. **Import Workflow**:
   - Click **Add Workflow** > **Import from File**.
   - Upload `docs/n8n-workflows/01-email-report-processing.json`.
   - Or copy content from the file and paste into N8N.

### 2. Configure Workflow
1. Double-click the **Email Webhook Trigger** node.
   - Note the Webhook URL (e.g., `/webhook/trading-reports`).
2. Verify connections to services (Scraper, Analyzer, Notification) are using the internal Docker network DNS (e.g., `http://playwright-scraper:8002`).
3. **Save** and **Activate** the workflow.

## Phase 5: Exposing to the Internet (Securely)

To receive email webhooks from providers like Mailgun/SendGrid, your webhook endpoint needs to be accessible.

### Option A: Cloudflare Tunnel (Recommended for Home Labs)
No port forwarding required. Safe and secure.

1. Install `cloudflared` on your server.
2. Authenticate: `cloudflared tunnel login`.
3. Create a tunnel: `cloudflared tunnel create trading-monitor`.
4. Configure `config.yml`:
   ```yaml
   tunnel: <Tunnel-UUID>
   credentials-file: /home/user/.cloudflared/<Tunnel-UUID>.json
   
ingress:
  - hostname: trading.yourdomain.com
    service: http://localhost:8001 # Forward to Email Webhook Service
  - service: http_status:404
   ```
5. Run the tunnel: `cloudflared tunnel run trading-monitor`.

### Option B: Nginx Reverse Proxy + Port Forwarding
1. **Port Forward**: Forward port 80/443 on your router to your server IP.
2. **Install Nginx**: `sudo apt install nginx`.
3. **Configure Site**:
   ```nginx
   server {
       server_name trading.yourdomain.com;
       
       location /webhook {
           proxy_pass http://127.0.0.1:8001;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   ```
4. **SSL**: Use Certbot (`sudo apt install python3-certbot-nginx`) to get a free Let's Encrypt certificate.

## Phase 6: Maintenance & Operations

```bash
# View logs for specific service
make logs-service SERVICE=ai-analyzer

# View all logs (follow)
docker compose logs -f
```

### Updating the System
```bash
cd /opt/trading-report
git pull origin main
make build
make prod
```

### Backups
```bash
# Backup database
make db-backup
# Backups are saved to ./database/backups/
```

- Check `http://<SERVER_IP>:5678` for N8N workflow executions.
- Check `http://<SERVER_IP>:8003/api/v1/health/status` for system health.
